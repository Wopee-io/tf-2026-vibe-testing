The team problem

Incomplete requirements.

Boundaries, defaults and state changes can be unclear. A test still needs a pass/fail decision.

Our design choice

Record the reasoning first.

Keep a trace from the requirement to the question, the assumption and the test.

Expected behaviour comes from requirements and explicit assumptions.

05 / Step 3 · spec-tests · designed workflow

Parallel work.
Explicit ownership.

Worklist→Helpers + smoke gate→Agents by story→Merge + run→ID coverage + report
Shared foundation

Check the base first.

The orchestrator owns shared helpers. Helpers act and read; tests hold expectations. A failed helper smoke test stops fan-out.

Independent work

One story per agent.

Up to four at a time, each with its own browser session, test file and output folder. Shared helpers stay read-only.

Traceable results

One rule per test.

Rule IDs connect tests to the worklist. @assumption keeps assumed behaviour identifiable. Failures retain their source.

App inspection supplies locators and data; expected behaviour keeps its documented source.
